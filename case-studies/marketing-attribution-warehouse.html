01 / Overview

Connecting marketing activity to registrations and sales

Email, web analytics, Salesforce, and WooCommerce all tracked different parts of the customer journey. There was no reliable ID linking a campaign click to a registration or order. I built a warehouse that brings those records together and keeps the match evidence with each result.

The original work used live organizational data. This public version uses generated records, but keeps the warehouse structure and matching rules so the report can be shown without exposing anyone’s information.

02 / Approach

Matching records with a confidence level

I try an exact email match first. When that is not available, the model can fall back to a company-domain match. The match type stays attached to the result, so someone reading the report can tell a direct connection from a weaker one.

A Python loader creates and populates the 32-table warehouse, including the attribution fact table that Power BI reads. Keeping the schema consistent matters because the report depends on specific fields and relationships.

04 / REFLECTION

What I learned while making it public

My first public loader produced a schema that was close to production, but not close enough for the existing Power BI report. Later, I removed some fields during sanitization that the revenue charts still needed. I went back and separated fields I could safely rename from fields the model depended on. That distinction now comes up much earlier whenever I prepare data for sharing.
